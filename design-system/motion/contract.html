Motion contract

The card that decides whether a design is portable. Every animation in a returned spec must satisfy all six rules — a spec that breaks one cannot be built in React Native without redesigning it first.

This is a hard constraint list, not a style guide. The app is React Native, not the web. Motion runs on a worklet thread through src/motion.js; anything outside that budget either cannot be expressed or drops frames on a mid-range Android.
  1. Only these four properties animate. opacitytranslateXtranslateYscalerotate
    Everything else is off-budget and will be rejected: background-colorwidthheightblurbox-shadowbackground-position
    Colour is excluded even though Reanimated can interpolate it on the UI thread — the app's surfaces are token-driven, and animated colour fights the theme system (a user can change palette and mode underneath you).
  2. Every motion must name a src/motion.js primitive. Write "enter with riseIn, stagger(i) at 60ms" — one call, one place. A spec that invents a new curve must say so explicitly and justify why an existing primitive will not do.
  3. Numbers, not vibes. Duration in ms, delay in ms, offset in dp, easing named from EASE. "Gentle fade" is not a spec. "fadeOut(), DUR.tap" is.
  4. Durations come from DUR.
    TokenmsUse
    DUR.tap120Press feedback, instant acknowledgements
    DUR.enter320Card and row entrances, screen change
    DUR.settle480Longer settles, count-ups
    DUR.celebrate900Reward moments only
    Off-ladder values need justification.
  5. Nothing loops indefinitely — except the existing ProgressBar shimmer, which is already built and stays as it is. This is a journalling app opened once a day; ambient perpetual motion reads as noise and costs battery.
    The one apparent exception is the frozen celestial set: RayFan and NightRays rotate once per 60s. They are pre-existing, frozen, and not a licence for new loops.
  6. Respect reduced-motion. Every entrance must degrade to a plain cross-fade when the OS asks for reduced motion. If a design only works with its movement, it is not finished.

What a usable spec looks like

"Perk rows enter with riseIn, stagger(i, 60), DUR.enter. The price card uses popIn on mount. CTA takes usePressScale(). Nothing loops. Under reduced-motion all three collapse to a cross-fade at DUR.enter."
"The perks gently cascade in with a soft blur that resolves as the card lifts, and the price gradient slowly shifts behind it." — three off-budget properties (blur, box-shadow lift, background-position), no named primitive, no numbers, and an indefinite loop.

The one thing that is never animated at all

The celestial set is frozen. BigSun, RayFan, NightSky, NightRays and BigMoon are never redrawn, restyled, recoloured or re-timed. A design may position them, size them, and animate their container (opacity, translate, scale) — nothing inside. See the Frozen card.
